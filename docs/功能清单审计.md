# 功能清单审计

判定标准：**不看代码里有没有这个词，只看有没有可执行的入口**。

grep 命中不算数——注释里提过、文档里写过，都算不上这个功能存在。

## 探测方式

`scripts/audit_list.py` 逐个试子命令：能进 `--help` 的就是存在的。

早期版本解析 `--help` 里的 `{a,b,c}` 来提取子命令，这不可靠——
抓到的第一组常常属于别的子命令的参数，而不是顶层子命令。
会导致"功能存在却判缺失"的假警报。

## 这份审计证明不了什么

**它只验证"有入口"，不验证"真机能跑"。**

输入法实际打出中文、指纹实际解锁、扫码实际识别、触摸板多指手势
实际生效——这些都需要真机。配方、框架、检查逻辑都在，
但没在设备上验证过。

同理，219 个配方的源码校验和还锁着 `checksum_pending`，
真实编译需要 ≥8 核 / 32G / 200G 的机器。
