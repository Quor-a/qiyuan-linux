# 如何改墨语言的编译器

先读这一份再动代码，能省下几个小时的困惑。

## 三份源码，两个编译器

| 文件 | 是什么 |
|---|---|
| `src/asm/*.s` | 手写 x86-64 汇编的**引导编译器**（seed），约 3200 行 |
| `src/mo/compiler_part{1..5}.mo` | 墨语言写的**真编译器**，拆成 5 个片段 |
| `src/compiler.mo` | 上面 5 个片段按顺序拼起来的结果（**不要直接编辑**） |

`src/compiler.mo` 是生成的：

```
cat src/mo/compiler_part*.mo > src/compiler.mo
```

改编译器要改 `src/mo/` 下的片段，然后重新拼接再构建。

## 最重要的规则：改代码生成必须改两遍

`bin/seed` 的职责是用它自己把 `src/compiler.mo` 编成 `bin/moc`。
于是任何**影响输出字节**的改动——新语法、新优化、改指令编码——
都必须同时在 `src/asm/*.s` 里实现一遍。

漏了会怎样？`verify_bootstrap.sh` 立刻报「自举不一致」：

```
Stage1 (seed 编译):  xxxx
Stage2 (moc  编译):  yyyy     <- 与 Stage1 不同
❌ 自举不一致
```

这是好事。自举要求 seed 与 moc 的产物**逐字节相同**，
所以它是最强的回归测试——本项目的多个编码错误都是它逼出来的。

### 什么不必镜像

只影响**诊断**的改动可以不镜像 seed。
例如「缺少 return 检查」只在 moc 里，seed 没有。

判断标准很直接：**`verify_bootstrap.sh` 只比字节，不比诊断。**

### `src/compiler.mo` 只能用 seed 支持的语法子集

seed 不支持一元 `&`、数组、结构体、`import`。
所以 `compiler.mo` 里只写二元 `&`（按位与），从不写 `&x`。

这是刻意的：保证 seed 永远能引导，自举链条不会断。
代价是编译器源码不能用自己最炫的特性。

## 日常流程

```
# 1. 改 src/mo/compiler_partN.mo
# 2. 拼接
cat src/mo/compiler_part1.mo src/mo/compiler_part2.mo src/mo/compiler_part3.mo \
    src/mo/compiler_part4.mo src/mo/compiler_part5.mo > src/compiler.mo
# 3. 构建 + 验证
make all
```

或者直接用：

```
./build.sh self bin/seed      # 只重建 moc
bash tests/run.sh bin/moc     # 跑测试
bash verify_bootstrap.sh      # 验证自举
```

### 症状离根因很远

踩过一次，值得单独记：某次加完特性，seed 突然报
`error: cannot open output`，且编出的编译器一跑就段错误。

真正的根因是 **`while` 分支里调了 `loop_push` 却漏了配对的 `loop_pop`**——
每编译一个循环栈顶就涨一格，最后越过 `lstk` 的边界，
写坏了几十 KB 之外的输出文件名。

排查顺序（可以复用）：

1. **先判定是工具坏了还是输入坏了**：拿"回退掉新特性"的编译器源码
   给当前 seed 去编。产物同样崩溃 → 工具坏了；正常 → 源码坏了。
2. **加探针**：在关键阶段（解析后、回填后、建 ELF 后）打印被踩坏的全局变量。
   能立刻把范围缩到某个阶段。
3. **算地址**：打印几个大数组的地址，用"被写坏的地址 − 数组基址"
   反推是哪个数组、下标多少。
4. **二分输入源码**：按顶层块切分，逐段喂进去。若"加一个空函数就能触发"，
   说明是**累积越界**，不是某个语法结构的问题。
5. **把可疑的新增函数改成空操作**对照验证。

结论：**手写汇编里新增 `lstk` 这类全局缓冲，必须有配对的压栈/弹栈。**
没有作用域和 RAII 兜底，漏一次就是几十 KB 之外的随机破坏。

## seed 的语法子集（重要）

`src/asm/*.s` 是手写汇编的引导编译器，只支持一个**子集**。
它唯一的任务是把 `src/compiler.mo` 编出来，
**用不到的语法就不实现**。

seed **不支持**的（因此 `compiler.mo` 里不能用）：

| 特性 | 说明 |
|---|---|
| 数组、结构体 | `compiler.mo` 只用标量与全局变量 |
| `import` | 单文件即可 |
| 字符字面量 `'a'` | 注意：`compiler.mo` 里只能写二元 `&`（按位与），不能写 `&x` |
| **复合赋值 `+=` 等** | 0.7.0 起 moc 支持，seed 不支持 |

判断标准很直接：

- **影响输出字节的改动，两侧必须镜像**，否则自举立刻报不一致
- **只影响诊断的改动，可以只在 moc 实现**
- **新语法若 `compiler.mo` 不用，可以只在 moc 实现**，
  但要像上面这样写清楚，免得后来人在 `compiler.mo` 里写了编不过的语法

## 加语言特性时的检查清单

1. `src/mo/` 里实现
2. 如果影响代码生成，**同步改 `src/asm/*.s`**
3. 加一个正常用例（`tests/NN_*.mo`，带 `# expect: N`）
4. 加一个错误用例（`tests/errors/eNN_*.mo`，带 `# expect-error: <片段>`）
5. 跑 `make all`

错误用例很重要——它们保证诊断不会在某次重构后悄悄失效。

## 内存布局

编译器自己管理堆，全部区域是 `heap + 固定偏移`，偏移常量在
`src/mo/compiler_part1.mo` 开头。**加新区域前先确认不与已有区域重叠**，
重叠会导致极难排查的段错误。

踩过一次：新增路径拼接缓冲时取了个看起来空闲的地址，
结果一走搜索路径就段错误，排查了很久才发现不是地址问题而是
不该用全局变量。能用 scratch 区或局部常量就别加全局槽位。

## 调试技巧

| 症状 | 方法 |
|---|---|
| 生成的程序段错误 | `objdump -D -b binary -m i386:x86-64 -M intel --adjust-vma=0x400000 out.elf` |
| 自举不一致 | `cmp -l a.elf out.elf` 找首个差异偏移，再反汇编该处 |
| 编译器自己段错误 | 逐行删减源码做 delta debugging，逼出最小复现 |
| 症状离奇（如"打不开输出文件"） | 见下文「症状离根因很远」 |
| 怀疑某个 pass | 先确认它在 seed 里是否存在——seed 只有语法子集 |

`tools/codesize.sh <旧编译器>` 可以逐用例对比代码段字节数，
用来验证优化是否真的生效（文件大小不会变，因为代码段补齐到页）。
