# 能力矩阵：这一轮做了什么、什么没做、为什么

版本 1.4.0（2026-10-08）

用户提了一张很长的清单。按「墨语言当前架构能不能做」分成四类。
**判断标准是架构，不是意愿** —— 做不到的是需要新后端或运行时，
不是"还没写"。

---

## 一、这一轮做完的 ✅

| 需求 | 交付 | 关键点 |
|---|---|---|
| 加密 / 解密 | `lib/crypto.mo` | SHA-256、CRC32、Base64、ChaCha20 |
| 打包 / 解压 | `lib/archive.mo` | tar 打包/列目录/解包；gzip / gunzip |
| 网络协议 | `lib/json.mo` + 1.3.0 的 HTTP | JSON 解析 |
| 权限 / 文件元数据 | 走 `syscall` + `fs.mo` | chmod / stat 等直接系统调用 |
| IDE | `tools/editor/` | Vim 语法高亮、VSCode tmLanguage |
| CI / 工作区 | `tools/ci/` | GitHub Actions、Makefile / CMake 接入片段 |
| CPU 计算应用 | `bench/matmul.mo`、`bench/sieve.mo` | 128×128 矩阵乘、10 万筛法 |
| 多语言配合 | `tools/ci/Makefile.integration` | 独立 ELF + 文本/JSON 接口 |

**为什么加密和压缩能做**：它们全是纯位运算，
墨语言不依赖 libc 反而成了优势——不需要链接任何库。

**tar / gzip 的取舍**：gzip 只实现 **stored 模式**（不压缩，但格式合法）。
deflate 需要 LZ77 + Huffman，单轮做不完且极易出错。
优先保证**系统 gunzip 能解**，压缩率留待后续。

---

## 二、依赖引用：已具备（不是这轮新增）

`import` 支持相对路径、`lib/`、`../lib/` 三级搜索，
递归解析、按路径去重、循环引用合法（符号表共享 + 回填）。

缺的是**包管理**（版本、远程拉取）。那需要网络 + 哈希校验，
组件都齐了，但组合成一个包管理器是独立的一期工作。

---

## 三、做不到：需要新后端或运行时 ❌

| 需求 | 为什么做不到 | 需要什么 |
|---|---|---|
| **交叉编译** | 只有一个 x86-64 后端 | 新增目标架构的代码生成 |
| **多种设备架构** | 同上 | ARM64 / RISC-V 后端 |
| **SDK 编译 / APK** | Android 需要 ARM64 + Bionic libc 约定 | 新后端 + 新 ABI |
| **硬件兼容** | 需要驱动 / 系统调用接口封装 | 属于运行时与平台层 |
| **GPU 计算** | 需要 GPU 指令或 OpenCL/CUDA 运行时 | 全新后端，量级最大 |
| **Git 克隆** | 需要 HTTPS/SSH 协议栈 + SHA-1 对象格式 + zlib 压缩 | 网络有了，但 git 协议是独立工程 |

**一句话**：墨语言只有一个后端。上面每一项都不是"加个库"，
而是**再写一个后端**。

其中 **WASM 后端相对最可行**：栈式、无系统调用，
但要从零产出 wasm 二进制，仍是独立的一期。

---

## 四、部分具备 / 有边界 ⚠️

| 需求 | 现状 |
|---|---|
| 网络 | TCP + HTTP 服务端（1.3.0）。无 TLS、无 UDP、无 DNS |
| 权限 | 靠 syscall，有 fd 级操作，无用户/组抽象 |
| IDE | 只有语法高亮。**无 LSP**：LSP 需要符号位置与类型信息，
而当前调试信息只有行号 |
| 压缩 | gzip 仅 stored 模式（格式合法，不压缩） |

## 五、这一轮踩到的三个真 bug

### 1. SHA-256 常量表从第 28 项开始全错

我把素数立方根序列写串了。**现象是"摘要能算出来但永远不对"**——
最难查的一类，因为它不崩、不报错。

定位方法：用 Python 把墨语言代码逐行模拟一遍，
如果模拟结果和实际一致 → 是算法逻辑错（不是语言语义问题）；
如果不一致 → 才是编译器 bug。这一步把问题范围砍掉一半。

### 2. tar 校验和字段宽度差一位

`oct_field` 写的是 7 位八进制（148..154），
我又用 `store8(154, 0)` 想写 NUL，结果把最低位数字覆盖成 0。
校验和凭空少一位，系统 tar 直接拒绝："not a tar archive"。

### 3. tar 遍历只跳了补齐、没跳数据

跳过 `pad` 却没跳 `sz` 字节的数据，于是第二个头读成零块，
只列出第一个文件。**这个 bug 是自读自写检测不到的**——
必须让系统 `tar -tf` 来验证才算数。

> 教训：**格式类功能要用外部工具验证，不能只用自己写的读函数验证。**
