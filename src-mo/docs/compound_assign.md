# 复合赋值运算符

状态：moc 已实现（0.7.0）；seed 不支持
日期：2026-10-08

## 1. 语法

```mo
i += 1;        # 等价于 i = i + 1
x -= 5;
x *= 4;
x /= 5;
x %= 5;
x &= 10;
x |= 4;
x ^= 3;
```

支持三种左值：

| 形式 | 例子 |
|---|---|
| 变量（局部 / 全局） | `g += 4;` |
| 数组下标 | `a[2] += 5;` |
| byte 数组下标 | `b[0] += 7;`（按 1 字节读写） |

不支持 `<<=` / `>>=`：`<<` 已经是双字符 token，词法层的 `set_tok` 只存两个字节，
要支持三字符得先改词法。留待需要时再说。

## 2. 实现思路

关键点是**复用二元运算的那套 `g_*` 函数**，而不是为复合赋值另写一套。

以 `x += e` 为例（此时 `rax` 是右操作数、`rcx` 是左操作数）：

```
load_sym(x)      ; rax = x 的原值
g_push_rax()     ; 左操作数入栈
parse_expr()     ; rax = e
g_pop_rcx()      ; rcx = x 的原值
g_add()          ; rax = e + x
store_sym(x)
```

好处是**语义与 `x = x OP e` 完全一致**，包括不可交换的减法和除法——
`g_sub` 算的是 `rcx - rax`（左减右），`g_idiv` 算的是 `左 / 右`，
直接复用就不会出现方向搞反的问题。

下标版本多一步：地址要先算出来存着，因为运算会占用寄存器。

```
index_addr(sy)   ; rax = 地址
g_push_rax()     ; 存地址
g_load_at()      ; rax = 当前值
g_push_rax()     ; 左操作数
parse_expr()
g_pop_rcx()      ; rcx = 当前值
g_compound(op)
g_pop_rcx()      ; rcx = 地址
g_store_at()
```

## 3. 词法：必须比单字符更早匹配

`+=` 必须作为一个整体 token 识别，否则会被拆成 `+` 和 `=`。

`lex_punct` 里把复合赋值的判断放在单字符回退之前：

```mo
if c == 43 { if d == 61 { return set_tok(43, 61, 2, p); } }   # '+' '='
```

`&=` 与 `&&`、`|=` 与 `||` 同理——先看第二个字符是不是 `=`。

## 4. seed 不支持（重要）

**seed（手写汇编的引导编译器）不支持复合赋值。**

这意味着 `src/compiler.mo` **不能**使用 `+=` 等写法，
否则 seed 编不过它，自举链条会断。

这不是疏漏，是刻意的取舍：seed 只负责把 `compiler.mo` 编出来，
它连数组、结构体、`import`、字符字面量都不支持——
复合赋值只是这份"不支持清单"上的又一项。

代价是墨语言自己的编译器源码不能用自己最方便的语法。
这在自举语言里很常见（Go 早期、Rust 早期都有类似约束）。

### 一次失败的尝试

我最初想在 seed 里也实现一遍，让它与 moc 保持一致。
词法层改好了（反汇编确认 `+=` 确实被识别成单 token）；
但 `parse_stmt` 的复合分支始终报 `syntax error`。

探针打出来的事实：

```
tokbuf[0] = 43 ('+')     tokbuf[1] = 61 ('=')     tok_kind = 4
compound_op() 返回 1      sym_lookup("i") 返回 1
```

也就是说——**分派前的每一步都对**，但复合分支内部没有执行到底。

继续往下定位的代价已经超过收益，我选择了**撤销 seed 侧的全部改动**，
把汇编源码从 0.6.0 的打包快照恢复，验证自举与 78 项测试均正常后才继续。

### 撤销时踩的坑

撤销脚本用 `s.index('    call next_token\n')` 定位起点，
但匹配到的是**文件里第一个** `call next_token`（在 `parse_program` 里），
而不是 `parse_stmt` 里的那个。结果把两个位置之间的内容整段删掉，
连 `parse_block` 一起没了，`ld` 直接报 undefined reference。

**教训：按内容定位时，要确认匹配的是不是唯一出现。**
差分脚本里用 `str.index` 而不检查唯一性，等价于闭着眼睛下刀。

这类撤销用打包快照整体覆盖更可靠——也是这次真正救场的办法。

## 6. 遗留

| 项 | 说明 |
|---|---|
| `<<=` / `>>=` | 需要三字符 token 支持 |
| seed 不支持 | `compiler.mo` 因此不能用 |
| 字段复合赋值 `s.f += 1` | 未实现（只做了变量与下标） |
| 复合赋值的类型检查偏宽松 | 右操作数类型目前不做严格校验 |
