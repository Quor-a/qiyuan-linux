# 墨语言结构体设计

状态：已实现（阶段一 · 第 4 周）
日期：2026-10-08

## 1. 语法

```
struct Point {
    x: i64;
    y: i64;
}

struct Box {
    v: i64;
    w: i64;
}

struct Outer {          # 字段可以是另一个结构体（嵌套）
    a: i64;
    in: Inner;
    b: i64;
}

fn main() -> i64 {
    let p: Point;       # 局部结构体
    p.x = 3;
    p.y = 4;

    let a: [3] Box;     # 结构体数组
    a[0].v = 10;

    return p.x + p.y + a[0].v;
}
```

全局结构体：`var g: Pair;`（数据段零初始化）。

## 2. 内存布局

结构体字段按声明顺序紧密排列，每个字段 8 字节（当前所有标量都是 i64）。
嵌套结构体**内联展开**，不是指针。

| 场景 | 布局 |
|---|---|
| 局部结构体 | 栈帧内 `nfields*8` 字节连续，基址为 `off0 = P - 8*(n-1)` |
| 全局结构体 | 数据段内 `nfields*8` 字节，零初始化 |
| 结构体数组 | `n * size` 字节连续，`a[i]` 地址 = 基址 + `i * size` |

## 3. 类型表示

类型统一编码为一个整数：

| 值 | 含义 |
|---|---|
| `0` | i64（标量或数组元素） |
| `>= 1` | 结构体索引 `+ 1` |

存于 `O_STY[sym]`（变量类型）与 `O_STFT[si*32+fi]`（字段类型）。
字节步长由 `ty_size(ty)` 得出：`0 → 8`，否则 `8 * nfields`。

结构体表：

| 区域 | 内容 |
|---|---|
| `O_STN[si]` | 结构体名（intern 偏移） |
| `O_STF[si]` | 字段个数 |
| `O_STFLD[si*32+fi]` | 字段名 id |
| `O_STFT[si*32+fi]` | 字段类型 id |

上限：32 个结构体，每个 32 个字段。

## 4. 代码生成

字段访问统一走「先算地址，再决定要不要 load」：

```
field_chain(ty):
    rax = 基址                     # 由调用方先载入
    while 遇到 '.':
        si = ty - 1
        fi = st_field(si, name)
        rax += fi * 8              # 常量偏移，fi==0 时跳过
        ty  = st_field_type(si, fi)
    return ty
```

- 返回类型 `0`（i64 字段）→ 追加 `mov rax, [rax]` 取值。
- 返回类型 `>= 1`（结构体字段）→ `rax` 里是地址，供后续 `.` 继续展开。

赋值 `p.x = v` 走同一条路径拿地址，`push rax` → 算右值 → `pop rcx` → `mov [rcx], rax`。

### 下标换算

原来数组固定 `shl rax, 3`。支持结构体元素后步长可变，
改为 `imul rax, rax, imm32`（`48 69 C0 imm32`），步长由 `ty_size` 得出。

## 5. 实现中踩的坑（二）：全局结构体被当成局部

第一版实现时，`parse_let` 与 `parse_global` 的结构体分支用了同一段替换文本，
结果全局结构体也走了局部变量路径（`sym_add(kind=1)` + `K_CUROFF`），
在函数里访问全局结构体会生成 `lea rax, [rbp-8]` 而不是 `movabs rax, 0x10000000+off`，
运行即 SIGSEGV。

**只在 main 里用全局结构体不会暴露这个 bug**（main 的 rbp-8 恰好可写），
所以测试必须覆盖「全局结构体在非 main 函数中访问」→ 测试 25。

## 6. 已知限制

- **结构体不能按值传参**，只能传 `&s` 指针后用 `load64/store64` 手动读写。
  按值传参需要拷贝语义，留到类型系统阶段统一处理。
- **没有 `->` 运算符**，指针访问结构体字段要写 `load64(p + 8)`。
- **结构体不能整体赋值**（`a = b` 会报 `cannot assign a struct value`）。
- **结构体数组不支持初始化列表**，`let a: [3] Box;` 之后逐个字段赋值。
  （`i64` 数组支持 `let a: [4] i64 = 5;` 常量填充。）
- **结构体必须在使用前声明**。编译器是单遍的，不做前向类型声明。
- **不支持结构体初始化列表**，`let p: Point;` 之后字段逐个赋值。

## 7. 实现中踩的坑

`i64` 在词法上是**标识符**（kind 1），不是关键字。所以判断字段类型时，
必须先问「是不是 `i64`」，再问「是不是结构体名」，顺序反了就会把
`x: i64` 当成未知结构体报错。

同样的顺序问题在 `let` / `var` 的类型位置上也存在，三处都按
`tok_is("i64") → struct → 报错` 的顺序处理。
