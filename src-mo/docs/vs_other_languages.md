# 墨语言 vs 其它语言：有什么，缺什么

调研时间：2026-10-08（v1.3.0）

按「能不能在墨语言现有架构下做出来」分成三类。
**能做的**已经做了，**要架构改动的**排在期 22 之后，**架构外**的基本不在 1.x 计划里。

---

## 一、能直接做（已实现）

### 网络 / HTTP ✅ 本轮新增

Python 有 `socket`、Go 有 `net/http`、Node 有 `http`——墨语言现在也有。
关键在于：墨语言直接产出 ELF64，而
`socket / bind / listen / accept / send / recv` **全是系统调用**，
不需要链接任何库。

```mo
import "net.mo";
let fd: i64 = tcp_listen(8080, 16);
let c: i64 = tcp_accept(fd);
tcp_send_str(c, "HTTP/1.0 200 OK\r\n\r\nhi");
```

`examples/httpd.mo` 是一个真的能用的 HTTP 服务：
静态响应、`?name=` 查询串、计数接口、404、每连接 fork。

**验证方式是个亮点**：测例在**同一个进程里 fork 出服务端与客户端**，
真实走 TCP 回环并校验 HTTP 响应。不启后台进程，测例自包含。

## 二、能做，但要改语言或编译器

| 别的语言有 | 墨语言缺 | 需要什么 | 排在 |
|---|---|---|---|
| `for` 循环 | 只有 `while` | 语法 + 代码生成（两侧镜像） | 期 23 |
| `switch` | 无 | 语法 + 跳转表 | 期 23 |
| 布尔类型 `bool` | 用 `i64` 的 0/1 | 类型系统扩展 | 1.x |
| 浮点 `f64` | 无 | SSE 指令 + 类型系统 | 1.x，优先级低 |
| 字符串拼接运算符 | 只有 `strcat` | 语法糖 | 低 |
| 完整寄存器分配 | 只有栈顶缓存 | **先要有 IR** | 期 22 |
| 闭包 / 匿名函数 | 无 | 需要堆上闭包环境 | 1.x |
| 泛型 | 无 | 类型系统大改 | 不在 1.x |

---

## 三、架构外：基本不在 1.x 计划里

| 目标 | 为什么难 |
|---|---|
| **安卓原生** | 需要 ARM64 后端 + Bionic libc 调用约定。当前只有 x86-64、且不用任何 libc。等于再写一个后端 |
| **Web / 浏览器** | 需要 WASM 后端或 JS 后端，同样是新的后端。WASM 相对可行（栈式、无系统调用），但要从零产出 wasm 二进制 |
| **Go 的 goroutine** | 需要调度器 + 栈增长，是运行时工程，不是编译器特性 |
| **C++ 的模板/RAII/异常** | 语言设计层面的大改，与墨语言「简单、自举」的目标冲突 |
| **Python 的动态类型/repl** | 需要运行时类型系统与解释器，等于另做一门语言 |
| **跨线程** | 需要 TLS、锁、线程创建；可以做但工作量不小 |

## 四、本轮踩到的两个坑

### 1. `strstr` 返回 0 是「找到了」，不是「没找到」

写测例时我写了 `if strstr(...) == 0 { return 失败; }`——
结果**匹配成功（下标 0）反而触发了失败分支**，
服务端一收到正确请求就退出，客户端拿到 EOF。

> 教训：返回「下标」的函数，-1 才是没找到。
> 0 既是合法下标又是假值，这类 API 天然容易写反。

### 2. 未使用变量检查有误报，已关闭

我加的 `unused variable` 警告对标准库大量误报：
数组几乎都通过 `&arr` 使用，参数也常直接进内建函数实参，
这两条路都不走 `load_sym`，于是被判为「没用过」。

同时发现 `O_SU`（使用标记数组）地址紧贴 `O_SK`，
符号数超过 492 就会越界覆盖符号类型表——已挪到安全地址。

**诊断默认关闭**（`K_WARN=0`）。理由：
误报的诊断比没有诊断更糟——它会训练人忽略警告。

---

## 五、一句话总结

墨语言缺的**不是「能不能做」，而是「后端数量」**：
它只有一个 x86-64 Linux 后端，所以安卓、Web、WASM 都是再写一个后端，
不是加个库。

而网络能力之所以能一轮就做出来，恰恰因为墨语言**不依赖任何 libc**——
系统调用是内核接口，跟语言无关。
