# 墨语言类型系统设计

状态：设计完成，实现中（阶段二 · 第 6 周）
日期：2026-10-08

## 0. 设计原则

**机器类型单一，静态类型分层。**

墨语言目前在机器层面只有一种东西：8 字节整数。指针是整数，结构体是连续 8 字节槽，
数组是连续整数。阶段二**不引入新的机器表示**（不做 bool/byte/float 的代码生成），
而是在编译器里建立一张真正的类型表，让下面这些事情在编译期被拦住：

- 对整数做 `->` 或 `.field`
- 对数组名做标量运算（忘记写下标）
- 函数调用实参个数不匹配
- 函数返回类型与 `return` 表达式类型不符
- 重复定义、未定义、作用域泄漏

这样阶段二的价值落在**诊断**上，而不是把代码生成器重写一遍。
新机器类型（byte/bool/float）留到后续版本。

## 1. 类型表示

引入**类型表**，每个类型一个 id：

| 区域 | 内容 |
|---|---|
| `O_TK[id]` | kind |
| `O_TA[id]` | aux1 |
| `O_TB[id]` | aux2 |

kind 编码：

| kind | 含义 | aux1 | aux2 |
|---|---|---|---|
| `0` INT | i64 整数 | — | — |
| `1` VOID | 无值（函数返回） | — | — |
| `2` STRUCT | 结构体 | 结构体索引 si | — |
| `3` ARRAY | 数组 | 元素类型 id | 元素个数 n |
| `4` PTR | 指针 | 指向类型 id | — |

预置 id：`0 = INT`，`1 = VOID`。其余按需分配，构造时线性查找去重。

上限：512 个类型。

### 为什么用类型表而不是打包整数

打包成 `kind | aux<<8` 写起来短，但数组元素类型又是一个打包值，
嵌套两层就放不下了。类型表用 id 间接引用，任意嵌套深度都成立，
且去重后 `int*` 在任何地方都是同一个 id，判等就是整数比较。

## 2. 类型的存放位置

| 位置 | 存什么 |
|---|---|
| `O_STY[sym]` | 变量（局部/全局/参数）的类型 id |
| `O_STFT[si*32+fi]` | 结构体字段的类型 id |
| `O_FRT[fsym]` | 函数返回类型 id |
| `O_FPT[fidx*8+pi]` | 函数第 pi 个形参的类型 id |

结构体表本身不变（`O_STN/O_STF/O_STFLD`），
`O_STFT` 从「旧编码（0=i64，>=1 结构体+1）」改为「类型 id」。

## 3. 类型规则

### 3.1 赋值兼容

`lhs = rhs` 合法当且仅当：

```
ty_eq(lhs_ty, rhs_ty)
```

**不做隐式转换**。整数赋给指针、指针赋给整数、`int*` 赋给 `struct*`
全部报错。这是刻意的选择：墨语言是系统语言，地址算术应该是显式的，
后面要加转换就加显式 `as` 语法，而不是在这里开隐式口子。

### 3.2 表达式类型

| 表达式 | 类型 | 备注 |
|---|---|---|
| 整数字面量 | INT | |
| 字符串字面量 | PTR(INT) | 值为数据段地址，指向字节序列 |
| 标识符（标量） | `O_STY[sym]` | |
| `a[i]` | `ty_a(array_ty)` | 元素类型 |
| `a[i].f` | 字段类型 | 元素必须是 STRUCT |
| `s.f` | 字段类型 | `s` 必须是 STRUCT |
| `&x` | PTR(`O_STY[x]`) | 数组取地址得 PTR(元素类型) |
| `a + b` | INT | 二元算术 |
| `-a` `~a` | INT | |
| `a < b` 等比较 | INT | 当前不引入 bool，真值仍是整数 |
| `!a` `a && b` | INT | 同上 |
| `f(...)` | `O_FRT[fsym]` | |
| `load8/load64` | INT | |
| `store8/store64` | VOID | 但现在当表达式用会报错 |
| `syscall` | INT | |

### 3.3 访问合法性

| 操作 | 要求 | 否则报错 |
|---|---|---|
| `x.f` | `x` 是 STRUCT | `field access on non-struct type` |
| `a[i]` | `a` 是 ARRAY | `subscript on non-array type` |
| `p[i]` | `p` 是 PTR 或 ARRAY | 指针下标按指向类型步进 |
| `f(...)` | `f` 是函数符号 | undefined symbol |
| `*p` | 暂不支持 | — |

### 3.4 函数签名

- 实参个数必须等于形参个数。
- 每个实参类型必须 `ty_eq` 形参类型。
- `return e;` 中 `e` 的类型必须 `ty_eq` 函数返回类型；`return;` 要求返回类型为 VOID。
- **不做**返回值非空检查（函数末尾没有 return 是允许的，行为未定义）。
  这条留到阶段二的诊断增强里做，避免误伤大量现有代码。

### 3.5 声明检查

- 同一作用域重复定义同名变量 → `duplicate definition`。
- 函数重名 → `duplicate definition`。
- 使用未声明标识符 → `undefined symbol`（已有）。
- 数组长度必须是正整数常量。

## 4. 类型传播的实现方式

墨语言没有结构体返回值，无法让 `parse_expr()` 直接返回类型。
沿用编译器现有惯例：用**全局变量**传递。

```
var R_ETY: i64 = 0;      # 最近一个表达式的类型 id
var R_LTY: i64 = 0;      # 最近一个左值表达式的类型 id
```

每个 `parse_*` 在返回前设置 `R_ETY`。赋值与调用点读取它做检查。

## 5. 诊断格式

阶段二把单行诊断升级为多行：

```
test.mo:3:19: error: undefined symbol 'qq'
    return a + qq;
                 ^^
  help: did you mean 'a'?
```

三行结构：

1. `文件:行:列: error: 消息`
2. 源码行原文 + 列指示符（`^^`）
3. 可选的 `help:` 建议

源码行通过从 `tokpos` 回退到行首、前进到行尾取出。

## 6. 与自举的关系

`src/compiler.mo` 自身必须继续能被 Stage0 汇编版 `seed` 编译，
因此编译器源码**不使用**数组/结构体/import 语法。
类型表用 `load64/store64` 直接访问，不需要新语法。

每次改动后跑 `bash verify_bootstrap.sh`，三级 md5 必须一致。
