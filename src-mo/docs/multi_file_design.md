# 墨语言多文件设计

状态：已实现（阶段一 · 第 2 周）

## 语法

```
import "lib.mo";      # 出现在文件顶部，可多次
```

## 编译模型

主文件与所有 import 文件**共享同一张符号表、同一块代码缓冲与数据缓冲**。
因此跨文件调用与跨文件全局变量访问都是天然的，不需要额外的链接步骤。

处理流程：

1. 读主文件到主缓冲区（`O_SRC`）。
2. 顶层遇到 `import` → 读该文件到独立缓冲区（`O_FILES` 起，每文件 1MB，最多 8 个）。
3. 保存并切换源码状态（基址、长度、扫描位置、行列），递归编译该文件。
4. 编译完恢复主文件状态，用 `set_pos` 回到原 token 继续。

## 跨文件调用的地址回填

函数符号在 `predeclare` 阶段登记时地址为 0，真实地址在生成函数入口时写入符号表。
所有调用点都进回填表，`resolve_all` 在最后统一写真实地址。
因此**定义顺序与文件顺序完全无关**，A 调 B、B 调 A、链式 A→B→C 都能工作。

## 源码基址

所有源码读取走 `sbyte(i) = load8(heap + K_SRCBASE + i)`，
切换文件只需改 `K_SRCBASE`，词法层无感知。

## 字符串字面量的双份存储

被编译程序里的字符串有两个用途，需要两份地址：

| 用途 | 地址 | 存储位置 |
|---|---|---|
| 生成的程序运行时使用 | `0x10000000 + off`（虚拟地址） | `O_DATA`（输出数据段） |
| 编译器自身读取（如 import 路径） | `heap + O_STRS + off` | `O_STRS`（编译器侧字符串池） |

`lex_string` 同时写入两处：`K_TIVAL` 存虚拟地址供代码生成，
`strpool()` 返回编译器可读地址。

**这个坑值得记住**：编译器源码里的字符串常量（如 `"test.mo"`）跑在 moc 自己的
数据段（vaddr `0x10000000`），直接用 `K_TIVAL` 是对的；
而被编译程序里的字面量在 moc 已映射区域之外，必须用字符串池。

## 诊断信息

每个 token 的行列由 `advance_lc` 增量维护（扫过源码字节时推进行/列）。
错误格式统一为：

```
文件名:行:列: error: 消息
```

- 语法错误指向**当前** token 位置。
- 未定义符号指向**上一个** token 位置（`K_PLINE/K_PCOL`），因为报错时已多读了一个 token。

## 循环 import

每个被 import 的路径在首次编译时登记到 `O_IMP`（存 intern 偏移）。
再次遇到同一路径直接跳过，因此：

- **重复 import 同一文件**：安全，只编译一次。
- **循环 import（a→b→a）**：安全，不会无限递归。

因为所有文件共享同一张符号表，`a.mo` 里调 `b.mo` 的函数不需要
b 已经编译完 —— 调用点进回填表，最后统一解析。所以循环依赖在墨语言里
是**合法的**，不像 C 需要头文件前置声明。

## 已知限制

- `import` 路径按相对当前工作目录解析，不做搜索路径。
- 单个文件上限 1MB，最多 8 个文件。
- 没有命名空间，`import` 进来的符号全进全局符号表，重名会互相覆盖（阶段二补）。
