# 多后端架构与对齐完整性

版本 1.7.0（2026-10-08）

---

## 一、四个后端

| # | 后端 | 入口 | 谁来跑 | 覆盖 |
|---|---|---|---|---|
| 1 | **原生 x86-64** | `bin/moc` | 直接执行 ELF | 全语法，零依赖 |
| 2 | **C** | `bin/mo2x ... c` | gcc / clang | 全架构、全系统 |
| 3 | **JS** | `bin/mo2x ... js` | node / 浏览器 | 算法子集 |
| 4 | **Python** | `bin/mo2x ... py` | python3 | 算法子集 |

**架构**：一份前端（分词 + 优先级递归解析），四个发射器。
前端只有一份，所以各后端的差异**只可能出现在发射层** ——
这是"对齐"能成立的前提，而不是靠逐个后端调出来的。

```bash
./bin/moc        prog.mo prog.elf     # 后端 1
./bin/mo2x prog.mo c  > prog.c        # 后端 2 → gcc
./bin/mo2x prog.mo js > prog.js       # 后端 3 → node
./bin/mo2x prog.mo py > prog.py       # 后端 4 → python3
```

## 二、对齐由测试锁定

`tools/multibackend_test.sh`：同一份 `.mo`，四个后端各跑一遍，
**退出码必须全部相同，且等于期望值**。

```
multibackend: 通过 10 / 失败 0（原生 + C + JS + Python）
```

用例：算术、数组读写、复合赋值、递归(fib)、结构体、else-if 链、
break/continue、位运算、除法取模、逻辑运算、嵌套循环 + 函数调用。

**没有这个测试，每个后端都只是"能跑"，而不是"对齐"。**

## 三、已知差异（写清楚，不藏着）

| 差异 | 说明 |
|---|---|
| C 后端无越界检查 | 原生后端有编译期 + 运行时检查，C 不管这个 |
| **JS 的 `/` 是浮点除** | 与整数语义不同 → 转译器**明确报错拒绝**，不生成错的代码 |
| JS 位运算按 32 位有符号 | `1 << 40` 会溢出，这与 JS 本身一致 |
| Python 的 `//` 与 `%` 对负数与 C 不同 | 向下取整 vs 向零取整 |
| Python 整数任意精度 | i64 溢出行为不同 |

> 原则：**宁可明确拒绝，也不生成看起来对但实际错的代码。**
> JS 的除法就是按这条处理的。

## 四、JS / Python 后端的能力边界

**支持**：变量、算术与位运算、比较、逻辑、if/else-if/else、while、
break/continue、函数与递归、数组、结构体、字符串常量与 `strlen`。

**不支持**（转译时明确报错）：
指针与取地址 `&`、解引用 `*`、内存读写 `load8/load64/store8/store64`、
`syscall`、`argc`/`argv`。

原因：JS / Python 没有线性内存与指针语义。
要给它们做内存，需要模拟一整块字节数组并把所有指针运算改写成索引，
那是另一个量级的工作。

## 五、这一轮挖出的编译器/翻译器问题

### 1. 括号表达式没输出括号（致命）

```mo
r = r + (a & b);
```
被生成为 `r + a & b` —— 优先级完全乱掉。
**在简单表达式上完全看不出来**，是多后端比对把它逼出来的。
（07_bit 用例：原生 163，C 后端 87。）

### 2. 函数调用没输出右括号

`cls(5) * 1000` → `cls(5 * 1000 ...`。同样是括号缺失。

### 3. 函数调用的左括号没被消耗

检测到 `(` 后没有 `TI++`，于是实参解析又把 `(` 当成括号分组，
多吃一层并吞掉实参后的 `)`，后面的 `expect_op(")")` 撞上别的 token。

### 4. 其它

- `break` / `continue` 在 C、JS 下漏了分号
- 结构体在 JS/Python 端没有实例化（JS 要 `new T()`，Python 要 `T()`）
- 缩进被算了两次（显式 `ind()` 与 `outs()` 内部的行首缩进叠加）
- Python 的函数前向声明没有冒号 → JS/Python 不需要前向声明，只对 C 输出
- 墨语言要求 `else` 紧跟 `}` 同一行，换行写会语法错误

## 七、一句话

多后端不是"多写几份代码"，而是**一份前端 + 多个发射器**，
再用自动化测试把「它们行为一致」这件事钉死。
这轮 10 个用例 × 4 个后端全部对齐 —— 差异只剩文档里列出的那几条。
