## 四、排查中发现的两个流程问题

**1. 改编译器必须改分片，不是改 `src/compiler.mo`。**
`make sync` 会把 `src/mo/*.mo` 拼接覆盖 `src/compiler.mo`。
我本轮直接改了 compiler.mo 三次，全部被 sync 静默覆盖，
表现为"改了没生效"，浪费了好几轮。

> 教训：先确认改动该落在哪个文件。有守护脚本时不代表它会自动帮你搬。

**2. 重复消耗 token。**
新加的分支里又调了一次 `expect(";")`，而 `parse_expr(); expect(";")`
在前面已经执行过 → 多吃一个 token → 后续语句整体错位，
报错落在**下一行**，很有迷惑性。

## 五、仍然存在的限制（诚实列出）

- 标准库多处固定容量：archive 64KB、dir 64KB、vec 无上限但 map 有
- `atoi` 不做溢出检查、`strcat` 不检查缓冲区
- C 后端不做数组越界检查（与原生后端的语义差异）
- 未使用变量警告默认关闭（对标准库有误报）
- Java/Go/Rust/C#/Swift/Ruby/Lua/PHP 八个后端本机无运行时，未验证
- 安卓只生成工程，未构建 APK（无 SDK/NDK）
- 完整寄存器分配未做（需先重构出 IR）
