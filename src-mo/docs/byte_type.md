# byte 与 ptr：让字符串处理能写下标

状态：已实现
日期：2026-10-08

## 1. 动机

0.3.0 之前，墨语言只有 `i64` 一种机器类型。字符串只能这样处理：

```mo
fn strlen(s: i64) -> i64 {
    let n: i64 = 0;
    while load8(s + n) != 0 {      # 手工算偏移
        n = n + 1;
    }
    return n;
}
```

全是 `load8` / `store8` 加手算偏移，读起来像汇编，写起来容易错。

更糟的是**越界检查完全用不上**——`docs/bounds_check.md` 里记过：
`wc` / `grep` / `sort` 三个真实程序的越界检查开销是 0%，
因为它们压根不走下标语法，全是 `load8(s + i)`。

现在有了 `byte` 与 `ptr`，可以写成：

```mo
fn strlen(s: ptr) -> i64 {
    let i: i64 = 0;
    while s[i] != 0 {
        i = i + 1;
    }
    return i;
}
```

## 2. 两个新类型

| 类型 | 含义 | 加载 | 存储 |
|---|---|---|---|
| `byte` | 1 字节无符号整数 | 零扩展到 i64 | 截断到低 8 位 |
| `ptr` | 指向字节的指针（`ptr(byte)`） | 同 `i64` | 同 `i64` |

```mo
let c: byte = 300;        # 存进去是 44（300 & 255）
let s: ptr  = "hello";    # s[1] 是 'e'，步长 1
let b: [8] byte = 0;      # 8 字节缓冲区，b[i] 步长 1
```

`byte` 变量在栈上仍占 8 字节（帧布局不变），只是读写指令宽度是 1 字节。
`byte` 数组则按 1 字节一个元素紧凑排布。

`ptr` 不带长度信息，所以 **`p[i]` 不做越界检查**——这和 C 的字符指针一致，
也是当前类型系统能表达的极限。要检查就得引入"胖指针"（指针 + 长度）。

## 3. 字符串字面量的类型改了

`parse_primary` 里字符串字面量的类型从 `ptr(i64)` 改成 `ptr(byte)`。
这让 `s[i]` 的步长从错误的 8 变成正确的 1。

现有用 `load8(s + i)` 的代码不受影响——它没有走下标路径。

## 4. 两个真 bug

### bug 1：byte 数组被后面的 i64 变量覆盖

现象：

```mo
let b: [8] byte = 0;
let i: i64 = 0;
while i < 5 { b[i] = 97 + i; i = i + 1; }
return b[4];        # 得到 0，应该是 101
```

只有 `b[0]` 是对的，`b[1..]` 全被冲成 0。

反汇编看得很清楚：

```asm
lea  rax,[rbp-0xf]        ; b[0]，b 占 [rbp-15, rbp-8]
mov  QWORD PTR [rbp-0x10], rax   ; i 在 rbp-16，占 [rbp-16, rbp-9]
```

`i` 的 8 字节槽 `[rbp-16, rbp-9)` 与 `b` 的 `[rbp-15, rbp-8]` **重叠**——
每次更新 `i` 都把数组内容覆盖一遍。

根因：`[8] byte` 只占 8 字节却没对齐到 8 字节边界。
原来的 `K_CUROFF = p - esz*n` 在 `esz=1` 时给出的下一个偏移，
会让 8 字节的 `i` 与字节数组共享空间。

修法：byte 数组把 `K_CUROFF` 压到 8 字节对齐：

```mo
if esz == 1 {
    sv(K_CUROFF, ((p - esz * n) - 7) & -8);
} else {
    sv(K_CUROFF, p - esz * n);
}
```

**只对 byte 数组应用**，避免改变其他数组已有的帧布局。

### bug 2：指针变量的下标取了变量地址，不是值

这个 bug 更隐蔽，而且在 `ptr` 类型出现之前**根本没有机会暴露**。

`index_addr` 原本对局部变量一律用 `lea`：

```asm
mov  eax, 0x10000010
mov  QWORD PTR [rbp-0x8], rax    ; s = 字符串地址
push 0x1
lea  rax, [rbp-0x8]              ; ← rax = &s，不是 s！
pop  rcx
add  rax, rcx
movzx eax, BYTE PTR [rax]        ; 读的是指针值的高位字节
```

对**数组变量**，`lea` 是对的——数组名就是基址。
对**指针变量**，`lea` 拿到的是"指针变量的地址"，
`s[1]` 于是读到了**指针值本身的第 1 个字节**，而不是它指向的内容。

修法：按符号类型区分。

```mo
if ty_kind(st) == 4 {
    load_sym(s);          # 指针变量：加载它的值
} else {
    g_lea_local(...);     # 数组变量：取地址
}
```

这个 bug 之所以一直没暴露，是因为 0.3.0 之前不存在 `ptr` 类型——
字符串只能声明成 `i64`，而 `i64` 不能做下标（会被"下标作用于非数组类型"拦下）。
**新类型一加进来，旧路径里的错误立刻现形。**

## 5. 标准库重写

`lib/str.mo` 已用 `ptr` + 下标重写：

| 函数 | 之前 | 之后 |
|---|---|---|
| `strlen` | `load8(s+n) != 0` | `s[i] != 0` |
| `streq` | `load8(a+i) != load8(b+i)` | `a[i] != b[i]` |
| `strcpy` | `store8(dst+i, load8(src+i))` | `dst[i] = src[i]` |

`memset` / `memcpy` / `memcmp` 保留 `load8` / `store8`——
它们操作的是原始内存而非字符串，语义上是字节数组，暂时没有对应的类型。

重写后 75 项测试全部通过，四个示例程序照常运行。

## 6. 后记：字符串字面量直接下标 + 一个分配 bug

### 可以直接下标了

`"hello"[1]` 现在合法，不必先赋给 `ptr` 变量。
实现在 `parse_primary` 的字符串分支里就地处理：
基址已在 rax，算偏移后按 1 字节加载。

### 全局 byte 数组原来一个字节都没分到

这是加 `byte` 之后立刻暴露的第二个分配 bug：

```mo
var b: [8] byte = 0;
var c: [2] i64 = 0;
```

`b` 的地址等于 `c` 的地址——**写 `b` 就是在写 `c`**。

根因在全局数组的分配循环：

```mo
let j: i64 = 0;
while j < esz / 8 {      # byte 的 esz 是 1，1/8 = 0
    dquad(0);
    j = j + 1;
}
```

`esz/8` 对 byte 是 0，一个字节都没写。局部数组那侧因为走了
不同的代码路径（`ty_size` 参与偏移计算），没这个问题。

修法：byte 数组单独按字节写，末尾补齐到 8 字节对齐。

```mo
while i < n { dbyte(v & 255); i = i + 1; }
while (gv(K_DLEN) & 7) != 0 { dbyte(0); }
```

### 一个能自己发现这个问题的测试

`tests/47_global_byte_array.mo` 故意在 byte 数组**后面**再放一个数组，
然后把两边的值混进返回值：

```mo
return (b[0] * 100000 + b[7] * 1000 + c[0] * 100 + c[1]) & 255;
```

数组没分到空间时 `c` 会被写成 `0x4847464544434241`，结果是 68；
分配正确时是 224。

**让测试去检测「有没有侵占别人」，而不是「自己能不能用」**——
后者在数组地址恰好落在可写的死区时也会通过。

## 7. 遗留

| 项 | 说明 |
|---|---|
| `ptr` 无越界检查 | 需要胖指针或显式长度参数 |
| 没有 `u8` / `i8` 区分 | `byte` 只做无符号零扩展 |
| ~~字符串字面量不能直接下标~~ | ✅ 0.5.0 已支持 `"hello"[1]` |
| `byte` 变量仍占 8 字节 | 浪费，但换来了帧布局不变 |
| ~~全局 `byte` 数组分配错误~~ | ✅ 0.5.0 已修复（原来一个字节都没分到） |
| `mem*` 系列仍用 `load8`/`store8` | 没有"字节数组"类型可表达 |
